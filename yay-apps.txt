# ---------------------------------------------------------------------------
# yay-apps.txt - the package set installed by setup-dotFiles.sh on Arch Linux.
#
# One package name per line. Blank lines and #-comments are ignored, so
# annotating this file is free. The reader is:
#
#     grep -vE '^[[:space:]]*(#|$)' yay-apps.txt
#
# Every surviving name is handed to a single `yay -S` transaction, and yay
# aborts the WHOLE transaction on one unresolvable name - a single typo here
# costs you every other package in the file. That is exactly how this list
# used to fail: `networkmanage` and `signal-deskto` (both typos) meant nothing
# at all was ever installed. Check a name with `yay -Si <name>` before you add
# it.
#
# Names resolve from the official repositories (core/extra) unless the comment
# above them says AUR; yay installs from both.
# ---------------------------------------------------------------------------

# --- virtualisation: KVM / QEMU / libvirt -----------------------------------
# VirtualBox was replaced by the native stack. VirtualBox needs an out-of-tree
# DKMS module rebuilt against every kernel you keep - and this list keeps four
# of them - while KVM is already in the kernel, so nothing has to be compiled
# and nothing breaks on a kernel upgrade.
#
# Membership of the "libvirt" group is what grants passwordless access:
# /usr/share/polkit-1/rules.d/50-libvirt.rules keys off exactly that group and
# nothing else. The setup script adds you to it; it takes effect on the next
# login.
libvirt
# qemu-full rather than qemu-base: it brings every architecture, the audio and
# SPICE backends and qemu-img. qemu-base alone gives you x86 with no sound and
# no display, which looks like a broken installation rather than a choice.
qemu-full
# The GUI, and the viewer virt-manager opens consoles with. virt-install comes
# with virt-manager and drives the same thing from the command line.
virt-manager
virt-viewer
# REQUIRED for the default NAT network. Without dnsmasq libvirt starts, the
# "default" network refuses to come up, and every new guest lands with no
# network at all - a failure that reads as a guest problem, not a host one.
dnsmasq
# UEFI firmware for guests. Anything modern - Windows 11, current Fedora,
# Secure Boot - expects UEFI rather than the SeaBIOS default.
edk2-ovmf
# Software TPM. Windows 11 refuses to install without a TPM 2.0 device.
swtpm
# libvirt reads host hardware details through it; without it the capability
# report is thinner and virt-manager guesses worse.
dmidecode
# OS detection in virt-manager: picks sane defaults for disk bus, network model
# and firmware per guest OS instead of falling back to the slow ones.
libosinfo
osinfo-db
# --- sharing a directory with a guest ---------------------------------------
# There are two mechanisms and they are not interchangeable; VirtualBox's
# single "shared folder" checkbox hid that distinction.
#
# 1. virtiofs - the fast one, a real filesystem passed through to the guest.
#    Host side is virtiofsd; the guest needs nothing beyond a kernel with the
#    virtiofs driver, which every current distribution has. Configure it in
#    virt-manager as Add Hardware -> Filesystem, driver virtiofs.
virtiofsd
# 2. SPICE folder sharing - slower, but works without touching the guest's
#    hardware definition and survives a running machine. phodav is the WebDAV
#    server; on Arch the guest-side daemon, spice-webdavd, ships INSIDE this
#    same package, so there is no separate spice-webdavd to install.
#    virt-manager exposes it as "Redirect folder".
phodav
#
# Guest-side only, listed here for reference rather than installed: install
# spice-vdagent in the guest for clipboard sharing and display auto-resize,
# and qemu-guest-agent for a clean shutdown and IP reporting to the host.
# Needed for qemu+ssh:// connections to a remote libvirt host.
openbsd-netcat
#
# Deliberately NOT here:
#   iptables-nft   - it is a "provides" of the iptables package that is already
#                    on every Arch system; naming it would only invite a
#                    replace-iptables prompt in the middle of the transaction.
#   bridge-utils   - gone from the Arch repositories; iproute2 does the job.
#   guestfs-tools  - genuinely useful for poking inside guest images, but it
#                    drags in a large appliance. Add it if you need it.

# ===========================================================================
#  Shared developer environment
#
#  Everything from here down mirrors packages/pacman.txt and packages/aur.txt
#  of the podman_base project. The Neovim, bash, zsh and tmux configuration in
#  this repository IS podman_base's configuration - the only difference is that
#  this host has internet, so plugins, language servers and parsers are fetched
#  at runtime instead of being baked into an image. The programs those configs
#  call still have to exist locally, and that is what this block installs.
#
#  So: these are not "nice to have" desktop tools. Each one is here because a
#  dotfile in this repository invokes it. Where that is not obvious - and
#  `tree-sitter-cli` on a desktop machine is definitely not obvious - the
#  section comment says which config file needs it and why.
# ===========================================================================

# --- language runtimes for Neovim (LSP servers, parsers, providers) ---------
# These are NOT here for their own sake - they are what the Neovim setup runs
# on. Mason installs lua-language-server, bash-language-server, basedpyright,
# json-lsp, yaml-language-server, typescript-language-server, clangd, stylua,
# shfmt and ruff. The JSON, YAML, TypeScript and Bash servers are npm packages,
# so nodejs and npm have to exist before Mason can install a single one of
# them; several formatters and debug adapters are Go or Python programs, hence
# go, python and python-pip.
#
# python-pynvim is Neovim's Python provider - without it `:checkhealth provider`
# reports a broken host program and any Python remote plugin refuses to load.
#
# tree-sitter and tree-sitter-cli generate and compile the parser list the
# Neovim configuration declares (bash, c, cpp, css, diff, dockerfile,
# git_config, gitcommit, gitignore, go, html, javascript, json, lua, luadoc,
# make, markdown, markdown_inline, printf, python, query, regex, rust, sql,
# toml, tsx, typescript, vim, vimdoc, xml, yaml). THAT is why a desktop machine
# ends up carrying a parser generator.
#
# python is already listed in the base system section above.
python-pip
python-pynvim
nodejs
npm
go
tree-sitter
tree-sitter-cli

# --- clipboard bridges ------------------------------------------------------
# The Neovim options set clipboard=unnamedplus, which delegates every yank to
# an external clipboard tool. Without one of these, yanking in nvim never
# reaches the system clipboard and the failure is silent. wl-clipboard covers
# Wayland sessions, xclip covers X11; installing both means the configuration
# works whichever session the machine boots into.
wl-clipboard
xclip
